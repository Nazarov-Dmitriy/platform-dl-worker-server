# Worker Processor: desktop

Первый рабочий вариант, 2026-10-27. Общий Electron-интерфейс для Windows/macOS,
существующий Agent/Journal/Resources работает в отдельном Node-процессе Electron.
Пользователь не создаёт JSON и не запускает команды. Закрытие окна скрывает его;
полный выход — через tray/menu bar. В Windows доступен необязательный автозапуск, по умолчанию выключенный.

## Запуск пользователя на Windows

Открыть `processor/desktop-release/win-unpacked/Worker Processor.exe`.
Всю папку `win-unpacked` сохранять вместе; один exe отдельно не переносить.
В окне указать HTTPS-адрес диспетчера, ID и DEVICE-токен своего устройства,
выбрать публичный `device-ca.crt` и рабочую папку, нажать «Сохранить и подключить».
Конфиг создаётся автоматически в системном userData (`Worker Processor`). Токен
сохраняется в `credential.bin` через Electron safeStorage/защиту ОС, в JSON его нет.
После повторного открытия поля заполнены; токен повторно вводить не нужно.

После сохранения подключения можно включить «Запускать при входе в Windows». При входе
в систему приложение подключится автоматически в фоне. Выключение флажка удаляет
его запись автозапуска. Папку приложения после включения не перемещать; токен в
запись автозапуска не попадает. macOS и перенос старого CLI-автозапуска ещё не реализованы.

В текущей Windows-сборке используются уже установленные FFmpeg/ffprobe из PATH.
Они не входят в этот первый комплект. Whisper/модели — отдельная приёмка. Подключение
к серверу ещё не доказывает обработку реального рабочего файла. Сборка локальная,
без цифровой подписи; Mac-сборка и реальный Mac пока не проверены.

## Разработка

Из processor: `npm ci`, `node node_modules/electron/install.js`, `npm run desktop`.
Runtime устанавливается явно: текущий npm-пакет Electron не принёс бинарник при первой
установке. `npm run desktop:pack` — папка приложения; `npm run desktop:dist` — установщик.
Разработчик может запустить electron-builder напрямую из node_modules, если PowerShell
npm.ps1 перехватывает аргументы после `--`.

`desktop:pack` не включает исходные тесты. Node runtime и production-зависимости
попадают в комплект. asar выключен для текущего первого варианта: исполнители и
native ONNX загружаются с реальных путей; переход на asarUnpack требует отдельной проверки.

## Воспроизводимый desktop-тест

`scripts/desktop-smoke.cjs` принимает DESKTOP_FIXTURE — путь к JSON изолированного
локального диспетчера: `url`, `deviceId`, `token`, `caPath`, необязательный `wrongCaPath`.
Разрешены только HTTPS localhost адреса. DESKTOP_EXECUTABLE выбирает собранный exe;
без него проверяются исходники через Electron. DESKTOP_SCREENSHOT — путь снимка.
Тест создаёт временный профиль, не читает рабочие аккаунты и удаляет свой профиль.
Проверяет HTTPS validation, реальный WSS, шифрование токена, фон, паузу, остановку
и повторное подключение сохранёнными настройками. Неверный CA проверяется при передаче wrongCaPath.

Renderer sandboxed, Node integration выключен, CSP запрещает сеть; preload раскрывает
ограниченные команды, main проверяет отправителя IPC. WSS проверяет выбранный CA;
унаследованный NODE_TLS_REJECT_UNAUTHORIZED удаляется в main и runner.
[Рекомендации Electron](https://www.electronjs.org/docs/latest/tutorial/security/).

## Следующая точка работы

Реальное задание через GUI на рабочем VPS; CI/сборка Mac arm64 и запуск на настоящем Mac;
автозапуск macOS и миграция старой Scheduled Task/LaunchAgent;
упаковка FFmpeg/ffprobe/whisper-cli с лицензиями; установка/подписи/обновление приложения;
защита смены устройства/рабочего диска при незавершённых заданиях, управление порогами.
Самостоятельное обновление приложения не реализовано и не связано с updater диспетчера.

Полная задача: [план](../../docs/plan/processor-desktop-plan.md),
[приёмка](../../docs/testing/processor-desktop.md).

Windows-контроллер: `node --test scripts/desktop-login.test.cjs`. Дополнительная
проверка `DESKTOP_CHECK_AUTOSTART=1` проверяет временную запись Windows и скрытое
автоматическое подключение. Тест удаляет собственную запись; рабочий автозапуск не включает.
