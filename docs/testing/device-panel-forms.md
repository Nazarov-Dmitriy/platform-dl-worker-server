Изменены: список/выбор устройства, подключение и токен, настройки устройства,
создание устройства/сайта/аккаунта. Каталог и операции моделей не перерабатывались.

## Поведение

- В строке устройства есть «Управлять». Карточка выбранного устройства показывает имя и ID.
- Кнопка выдачи и полученный токен явно называют выбранное устройство и его ID;
  на время выдачи переключение устройства блокируется.
- OWNER может удалить выбранное устройство после подтверждения имени/ID. Токены
  отзываются, текущая сессия закрывается, устройство исчезает из активного списка.
  Существующие задания и назначения сохраняют ссылку на историческую запись.
- Устройство с OFFERED/RUNNING/CANCELLING/RELEASING назначением не удаляется;
  интерфейс просит дождаться завершения. Нельзя вернуть удалённое устройство через
  PUT/CLI enabled или выдать для него новый DEVICE-токен.
- Во всех четырёх формах поля, checkbox-группа и действия имеют отдельные строки.
  Рабочая папка занимает полную строку, числовые поля идут парами; кнопки не занимают колонку поля.

## API и данные

`DELETE /api/v2/admin/devices/{id}`: OWNER session + CSRF + If-Match `"revision"`.
Успех 204; неизвестное/удалённое устройство 404; активное назначение/конфликт версии 409;
отсутствующий revision 428; чужая роль/CSRF 403.

Миграция SQLite 6 добавляет devices.deleted (default 0). История не удаляется физически.
Прежние устройства, токены и QUEUED-задания сохраняются при переходе с версии схемы 5.
Возврат предыдущего бинарника требует восстановления снимка прежней схемы —
штатный updater сохраняет и восстанавливает полные данные при неудачном обновлении.
