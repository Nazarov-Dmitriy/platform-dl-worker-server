# Соединения SQLite в службе обновления

2026-10-27. При установке 0.1.9 служба 0.1.8 получала database disk image is malformed в wait_idle. Свежий read-only quick_check возвращал ok. В /proc службы найдено много открытых dispatcher.db/WAL и удалённый dispatcher.db-shm.

Причина: with sqlite3.connect(...) управляет транзакцией, но не закрывает соединение. После жизненного цикла контейнера удерживались устаревшие WAL/SHM-дескрипторы. Чтения переведены на contextlib.closing; maintenance явно коммитит запись перед закрытием. Аналогично закрывается соединение экспортёра manage.py. Ошибка чтения SQLite получает отдельное безопасное сообщение в панели.

- 18 unittest в Linux-контейнере Python 3.12 — PASS; включая успешное обновление, откат, сохранение ручного обслуживания и явное закрытие каждого соединения.
- Исправлены host update.py/manage.py, исходные файлы сохранены в резервной папке службы.
- Перезапущена только служба обновления; диспетчер не перезапускался.
- Проверка VPS: quick_check ok, active assignments 0, API /status 200, удерживаемых DB-дескрипторов службы 0.
