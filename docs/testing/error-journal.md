# Единый журнал ошибок — приёмка Worker

Дата: 2026-11-17. Обновлено: 2026-11-21: закрыта владельцем без стендового прогона EJW-*. Статус: сценарии EJW-* не объявлены PASS.
План: [Worker](../plan/error-journal-plan.md).
Связанные проверки: [Backend](../../../LRIGHT/serverBreasts/docs/testing/error-journal.md), [Frontend](../../../LRIGHT/front/docs/testing/error-journal.md).

Подготовка: отдельный экземпляр dispatcher с errors.sqlite в тестовом томе, два сайта с действующими токенами, владелец, существующий аккаунт без прав владельца для проверки отказа и тестовое устройство. Новые роли и несколько владельцев не входят в первый выпуск. Сиды ещё не созданы: подготовить фиксированные eventId, occurredAt/receivedAt, не менее 60 групп для пагинации, группы в каждом статусе и выбранные примеры; manifest без токенов. Для TTL использовать управляемые часы/fixtures отдельной БД, не менять часы production. Исполняемых тестов нет; ниже реестр актуальных ID. Каждый сценарий меняет только тестовую диагностику, кроме явно отмеченного media-smoke. Записывать release, дату, зону, ширину и результат каждого прогона.

## Приём, группировка и границы

- [ ] **EJW-01 — durable ACK и дубли.** Роль: доверенный сайт/устройство.
  - [ ] **1.** Передать валидный пакет, повторить после потери ACK, перезапустить диспетчер; проверить один случай на eventId и сохранение после рестарта.
  - [ ] **2.** Передать пакет с одной невалидной/oversized записью; проверить отказ без частичного сохранения. Повтор eventId с другим payload даёт конфликт по контракту.
- [ ] **EJW-02 — fingerprint и корреляция.** Роль: владелец.
  - [ ] **1.** Передать одинаковый сбой с разными ID ресурсов/release и отличающиеся сбои из front/back/другого сайта.
  - [ ] **2.** Проверить группировку повторов, разделение источников/сайтов, связь по operationId и точный счётчик периода без дублей доставки.
- [ ] **EJW-03 — права и безопасность.** Роль: сайт A, сайт B, аккаунт без прав владельца.
  - [ ] **1.** Попробовать подменить site/source, читать журнал, менять группу и использовать действующий токен сайта для admin API; проверить запрет. Журнал доступен только владельцу. Site ingress отвергает source=worker.
  - [ ] **2.** Передать HTML и фиктивные секреты в message/stack/context; в БД нет секретов, панель отображает текст без выполнения HTML. Мутация без штатной CSRF/session защиты отклоняется.

## Хранение и смена состояния

- [ ] **EJW-04 — TTL и выбранные примеры.** Роль: владелец; fixtures с возрастом до/после 14 дней.
  - [ ] **1.** Добавить группу в favorite, другую взять IN_PROGRESS; проверить сохранение карточки и выбранного примера атомарно.
  - [ ] **2.** Запустить очистку; обычные старые события/пустые группы удалены, выбранные примеры защищены, последующие невыбранные повторы удаляются по TTL. Полученный duplicate не продлевает срок.
  - [ ] **3.** Снять favorite при IN_PROGRESS — защита остаётся; завершить разбор без favorite — после предупреждения защита снята и старое удаляется следующей очисткой. Проверить предел выбранных примеров и гонку pin/cleanup.
- [ ] **EJW-05 — настройки и повтор после исправления.** Роль: владелец.
  - [ ] **1.** Изменить срок 14→7 дней; проверить предупреждение и удаление только незащищённых событий при следующей очистке.
  - [ ] **2.** Для сохранённой RESOLVED-группы принять новый случай другой версии; группа становится NEW, история/пример остаются. IGNORED сохраняет статус. Полностью удалённая группа появляется заново без обещания старой истории.

## Просмотр и эксплуатация

- [ ] **EJW-06 — периоды, фильтры и раскрытие.** Роль: владелец, зона Europe/Moscow.
  - [ ] **1.** Подготовить события вокруг московской полуночи с различающимися occurredAt/receivedAt; проверить «Сегодня», «Вчера», «За неделю» (сегодня и шесть предыдущих дней), «За всё время» и свой диапазон. Показаны точные даты/зона; UTC [from,to) и статистика по receivedAt корректны, окончание своего диапазона включает день целиком. Неверный порядок дат отклоняется; неприменённые даты не меняют список и подпись применённого периода.
  - [ ] **2.** Выбрать сайт и front/back, раскрыть несколько строк, открыть связанный Backend/Frontend случай, сохранить пример и заметку; список, фильтры и позиция сохраняются, запись видна после перезагрузки. Стек или явное его отсутствие, контекст, версия, времена и ID доступны непосредственно под строкой.
  - [ ] **3.** Проверить отдельную область Worker: системные события не попадают в ошибки сайта даже при связанном jobId; фильтры сайта/front/back скрыты. Сводка охватывает все страницы фильтра; число впервые появившихся групп не подменяется числом групп со статусом NEW.
- [ ] **EJW-07 — отказы и media-smoke.** Роль: оператор стенда; меняет тестовые задания/диагностику.
  - [ ] **1.** Имитировать locked/full diagnostics DB, поток событий и недоступный sink; проверить честные отказы/counters, ограниченные ресурсы и отсутствие рекурсивного шторма.
  - [ ] **2.** При очистке/checkpoint и потоке событий выполнить контрольное media-задание; измерить время/очередь относительно baseline и проверить успешную обработку. Восстановить диск/лимиты, удалить только тестовые артефакты.
  - [ ] **3.** Обновить/перезапустить поставку и восстановить backup на отдельном экземпляре; favorite/IN_PROGRESS и выбранные примеры сохранились.

Экраны: «Ошибки → Сайты / Worker», быстрые периоды и свой диапазон, раскрытие под строкой, сохранённые примеры и действия разбора, экспорт, разрешённые действия сайта.

- [ ] **EJW-08 — Desktop, 1440×900 и широкий монитор 3440×1440.** Владелец выбирает вчера/front, раскрывает стек, добавляет favorite/заметку и сворачивает строку; текст читается, действия и пагинация доступны, loader/error/retry корректны. Контент центрирован и ограничен 1480px как в существующей панели, фильтры не растянуты на весь монитор.
- [ ] **EJW-09 — Mobile, 390×844.** Владелец открывает фильтры, меняет дату/source, раскрывает карточку и снимает защиту с предупреждением; нет потери действий и горизонтального скролла страницы, длинный стек прокручивается внутри своей области.

- [ ] **EJW-10 — существующее подключение сайта и разрешение сбора.** Роль: владелец, сайт с действующим токеном.
  - [ ] **1.** Включить «Сбор ошибок» рядом с остальными действиями; отправить front/back через Backend с действующим токеном без выдачи нового. Проверка подключения и последнее событие доступны в настройках.
  - [ ] **2.** Выключить действие: диагностический ingress отказывает, остальные разрешённые media-действия и токен продолжают работать, накопленные ошибки доступны владельцу. Включение восстанавливает приём. Отсутствие ошибок не показывается как доказанный обрыв связи.
- [ ] **EJW-11 — пагинация и согласованная сводка.** Роль: владелец; не менее 60 групп.
  - [ ] **1.** Проверить размер по умолчанию 25 и варианты 10/25/50, предыдущую/следующую страницу, диапазон и общее число групп. Повторы не занимают отдельные строки группового списка. Нет загрузки всего списка в браузер.
  - [ ] **2.** Сменить сайт/источник/период/размер страницы: переход на первую страницу с сохранением остальных фильтров. Сводка относится ко всему фильтру и согласована со снимком списка; поступление событий между запросами не создаёт ложных позиций/дублей.
- [ ] **EJW-12 — полный отчёт и CSV/JSON.** Роль: владелец.
  - [ ] **1.** Скопировать полную ошибку и скачать JSON из раскрытия: сообщение/причина, стек, контекст/breadcrumbs, версия, времена/зона, ID, выбранный и включённые примеры, статистика и история сохранены. При запрете Clipboard API доступен выделяемый текст для ручного копирования.
  - [ ] **2.** Скопировать общий отчёт и выгрузить CSV при нескольких страницах: включены все группы/доступные примеры по применённому фильтру, в том числе с последней страницы. Период/источники/сайт, время формирования и итоговые числа верны. Удалённые TTL события не заявлены как восстановленные.
  - [ ] **3.** Открыть CSV в Excel: UTF-8 BOM, разделитель `;`, кириллица, кавычки и многострочные стеки корректны; формулы не исполняются. Групповые счётчики и строки событий обозначены так, чтобы их не суммировать повторно. Секреты отсутствуют во всех форматах.
  - [ ] **4.** Проверить большой объём/лимит/ошибку выдачи: явный отказ или управляемая выгрузка, без молчаливой обрезки до первой страницы и без ложного сообщения об успехе.

После прогона снять fault injection, восстановить настройки, очистить изолированные данные согласно manifest. Результаты contract/Go/processor, интеграции и Desktop/Mobile учитывать отдельно; при отсутствии стенда отметить BLOCKED с причиной.
