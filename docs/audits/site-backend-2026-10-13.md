A. Контракт и настройки

- Токен зашифрован, в API только tokenSet, в логах режется; смена URL/токена не срывает принятую попытку — готово в коде.
  JobSettings + EncryptedStringConverter; снимок service_url/token в JobAttempt
- HTTP: таймаут 3/10 с, тело 1 MiB, без редиректов, адрес без userinfo/query/fragment — готово в коде.
  ExternalJobClient, ServiceAddress. HTTP разрешён не только localhost — для прода нужен HTTPS.
- Клиент GET /api/site/operations, POST /api/site/jobs, GET /api/site/jobs/{id} — готово в коде.
- Статусы ACCEPTED/QUEUED/RUNNING/SUCCEEDED/FAILED/REJECTED, проверка ID и состава results — готово в коде.
- Версия протокола и переход с ZIP на динамический HLS — требует доработки. Version нет; MediaTranscodeJobHandler → hls.zip.
- Настройка: нужна строка job_settings (URL+токен). Сейчас нет → дефолт SERVER. Check к живому диспетчеру не выполнялся.

C. Видео и резерв
- Живой путь урока/канала: тот же упаковщик и настройки сайта — готово в коде.
  LessonVideoProcessingService, ChannelPostVideoProcessorImpl → HlsPackagingServiceImpl
- media.transcode в очередь из редактора урока/канала НЕ ставится. Handler есть, продюсера нет.
- FFmpeg в образе: apt ffmpeg + libwebp, WORK_DIR /tmp/server-hls — готово в Dockerfile/compose. На VPS не проверял (кодеки, диск, RAM).
- COPY / ENCODE / SKIP_UPSCALE — готово в коде (VideoPackagingPolicy + packageVod). Тесты VideoPackagingPolicyTest, SmartPackagingFfmpegTest.
- Внешнее задание передаёт полный снимок профиля (качества, битрейт, copy-правила), а не «720p» — требует доработки.
  MediaTranscodeJobHandler.qualities() читает params.quality, иначе P720.
- Резерв видео на сайте без моделей — готово в коде (живой HLS). Внешний transcode этим путём не пользуется.
- Реальное play/seek/качество на тестовом ролике — не проверено в runtime.


D. Хранилище и публикация
- Presign GET/PUT, ключей S3 наружу нет — готово в коде. JobObjectStoreImpl. TTL по умолчанию 20 мин (JOBS_WORKER_PRESIGN_TTL).
- Обновление ссылок той же попытки: при повторном POST — да; после ACCEPTED только GET статуса, ссылки не освежаются — требует доработки (очередь длиннее TTL).
- Приём перечня HLS-файлов и выдача ссылок на сегменты — требует доработки. Сейчас один ZIP.
- Разные попытки → разные ключи: outputs = jobs/{jobId}/{name}, не attemptId. После fail объекты чистятся. Старый PUT vs новый пакет — слабо.
- Проверка реального размера/состава/плейлистов/хеша — требует доработки. Есть только сверка name/objectName/bytes из ответа, без HEAD S3 и разбора m3u8.
- Атомарная публикация живого HLS: заливка каталога, потом saveHlsPackage/replaceWithHlsPackage, потом READY — готово в коде для урока/канала. Для внешнего ZIP: complete по метаданным диспетчера, объект на диске не проверяется.
- Очистка: успех живого видео — исходник удаляется (канал явно, урок temp). Очередь jobs: при fail чистятся outputs, sourceObject не удаляется. Доп. операция не должна сносить видео — для transcribe так (текст отдельно). Неполное совпадение с чеклистом — доработка очистки очереди.


E. Расшифровка, субтитры, состояния
- Аудио → сплошной текст оригинала, без обязательных таймкодов — готово в коде.
  ChannelAudioTranscriptServiceImpl, audio-transcript-api.md, AudioTranscriptApplier
- Каталог языков от установленных моделей диспетчера — требует доработки. Есть справочник субтитров сайта (SubtitleCatalogService), не каталог моделей.
- Ручные субтитры к видео урока, VTT/SRT, allowlist — готово в коде. LessonSubtitleService, FileTypeAllowlist.MEDIA.
- Частичный результат (видео + успешные дорожки, список несделанного) — требует доработки. Протокол этого не описывает; сайт не принимает.
- Недоступная доп. операция → ручной ввод, не fail видео — готово для аудио (TRANSCRIPTION_UNAVAILABLE, manualEntryOffered). Для субтитров видео автонет — только ручная загрузка.
- Ожидание/прогресс/отмена/ошибка/уведомление: у урока/канала PROCESSING/READY/FAILED + notify. У внешней задачи progress 0..1 на попытке, отмены нет. Фронт редактора видео через очередь — отдельная задача (media-service-editor).
