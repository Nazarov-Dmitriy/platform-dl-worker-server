# Проверка текущей готовности и следующие задачи

Дата: 2026-10-13. Проверены текущий worker-server, отчёты этапов 4–7,
точки интеграции локального serverBreasts и существующие дорожки фронтенда.
Production VPS, рабочие задания, .env, реальные веса моделей и Mac не проверялись.
Исходный код не исправлялся: это аудит и порядок следующих работ.

## Что подтверждено

В коде есть очередь Go/SQLite, WSS, FILE-видеопуть FFmpeg/HLS, передача файлов,
публикация, каталог/команды моделей, аккаунты/панель, snapshot/restore/maintenance,
Compose и скрипты запуска. На Windows заново прошли go vet, go test, сборка,
валидатор контрактов и 21 Node test без пропусков с реальным тестовым диспетчером.
На Linux/Docker также прошли все 21 Node test без пропусков, включая сборку
Go-диспетчера и полный FILE-видеопуть. Полный Go race-прогон текущих этапов 4–7
в этом аудите не повторялся. Тесты распознавания/перевода используют catalog-test,
а не реальные модели.

Отметки «этапы 1–7 реализованы» не означают готовность запуска сайта. README ещё
указывает 1–4; задание интеграции сохраняло старое описание отсутствующего runtime.
Документы нужно привести к единому состоянию после закрытия перечисленных пробелов.

## Сначала исправить в worker-server

1. **Повтор обработки при продлении права.** `processor/src/agent.ts:422`
   запускает startJob, если ещё нет r.executor. Во время ожидания ссылки/скачивания
   его ещё нет, а для аудио он не создаётся. Следующий grant запускает runJob заново.
   Изолированный воспроизводитель с двумя допустимыми grants показал starts=2 вместо 1.
   Нужен отдельный флаг/Promise запуска всей попытки и тест долгого скачивания,
   повторного grant, reconnect и аудио. Это отдельная проблема от атомарного назначения Go.

2. **Настоящее распознавание блокирует управление.** addSpeech вызывается в основном
   процессе Agent. `speech.ts:94` и `speech.ts:185` используют execFileSync для
   whisper-cli и извлечения аудио с таймаутом до часа. В это время heartbeat,
   продление, отмена и обработка ответов не выполняются. Распознавание нужно вынести
   в контролируемый исполнитель с независимым сторожем, как видео. Проверить реальный
   длинный звук, потерю связи и остановку дерева процессов.

3. **Автоопределённый язык подменяется английским.** `speech.ts:101` возвращает en
   при sourceLanguage=auto независимо от результата Whisper. Получать фактический
   язык из машинного вывода исполнителя; проверить русский/другой неанглийский файл.

4. **Настоящий перевод не реализован.** `translateCues` поддерживает catalog-test;
   для остальных исполнителей возвращает EXECUTOR_UNAVAILABLE (`speech.ts:173`).
   NLLB в catalog.ts содержит SHA256 из повторяющихся a и URL страницы модели,
   не готового пакета. Нужно подключить реальный переводчик, проверяемую поставку,
   размеры/хеши и проверку исполнителя перед ACTIVE/объявлением ONLINE.
   Каталог сейчас не является доказательством возможности перевода.

5. **Установка моделей требует проверки реального HTTP-пути.** models.ts использует
   redirect:error для загрузки, а встроенные Whisper URL указывают на Hugging Face
   resolve/main. Проверить перенаправления и настроить ограниченный безопасный переход
   на допустимые адреса CDN; закрепить ревизию/файл и фактические хеши/размеры.
   На аудите большие веса не скачивались.

6. **Уточнить модель для коммерческого сайта.** В официальной карточке NLLB-200
   указаны CC-BY-NC-4.0 и исследовательское назначение без production deployment:
   https://huggingface.co/facebook/nllb-200-distilled-600M . Для оплачиваемого сервиса
   выбрать подходящую по условиям модель/поставщика до подключения настоящего перевода.

7. **Довести эксплуатационные мелочи этапа 7.** Cookie Secure определяется только
   r.TLS в admin_http.go:85, тогда как предложенный Nginx отправляет HTTP на Go.
   Нужна корректная конфигурация доверенного HTTPS-прокси/режима cookie и тест.
   Согласовать client_max_body_size 1m с лимитом metadata 8 MiB. Проверить установщики
   на свежих ОС, пути с пробелами, Windows ACL файла токена, создание LaunchAgents.
   «Обновление» панели пока делает maintenance/snapshot и предлагает вручную заменить
   образ — автоматического обновления и готового установщика с Node runtime нет.
