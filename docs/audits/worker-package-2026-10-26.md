# Пакет worker install — 2026-10-26

Взамен сложной двухконтейнерной установки реализован deploy/package и корневая
команда worker. Готовый архив распаковывается в выбранную папку, затем выполняется
sudo bash worker install. Пакет показывает полный путь, спрашивает IP, логин,
выбранный владельцем пароль. Все данные находятся в instance рядом с пакетом.

Сам образ по умолчанию выполняет launch: инициализирует владельца только при
пустой базе, создаёт CA и сертификат, обслуживает HTTPS/WSS и продлевает сертификат
внутри процесса. Отдельные nginx/systemd certificate timers не требуются. Сохраняется
постоянный том /data; development serve остаётся доступным для прежних стендов.
CLI health проверяет настоящий TLS с нужным SAN и внутренним адресом, не открывая БД.

В панели добавлена только функциональная ссылка «Скачать сертификат для Mac и Windows».
GET /device-ca.crt отдаёт исключительно публичный CA без авторизации, чтобы файл можно
было получить и с экрана входа. Приватные блоки PEM исключаются из ответа. Управление
адресом подготовлено в owner-only GET/PUT /api/v2/admin/connection с CSRF; новый дизайн
панели и формы дополнительных настроек будут обсуждаться отдельно.

В архиве один образ и CLI. Из Git образ собирается автоматически. Переезд через
worker export останавливает старый экземпляр, сохраняет весь пакет и состояние;
вторая копия одновременно не запускается. Поддержан отдельный WORKER_PROJECT_NAME
для изолированной проверки рядом с рабочим сервисом.

Проверки PASS:
- Go test для cmd/dispatcher, internal/dispatcher, internal/servercert;
- Linux Docker go vet ./... и go test -race ./...;
- три Python/Linux unit: адреса, владельцы/права конфигурации, запрет symlink;
- ShellCheck worker и deploy/package/package.sh;
- изолированный VPS smoke: один контейнер, выбранный пароль, видимый instance,
  скачивание CA из панели, Secure cookie, WSS 101, повторная установка и полный
  переезд с сохранением аккаунта, сессии, устройства и токена.
