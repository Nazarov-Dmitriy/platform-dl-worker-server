# Этап 4: файлы, FFmpeg и публикация видео

Дата: 2026-10-13. Реализованы рабочие каталоги, прямые GET/PUT, упаковка HLS и
HTTP transfer/publication диспетчера. Соседние serverBreasts/front, production VPS
и пользовательские медиа не изменялись.

## Реализация

Очередь по-прежнему хранит только записи. Обработчик запрашивает исходник после
lease.granted; сайт выдаёт краткоживущие URL той же попытки. Диспетчер не проксирует
байты и не отдаёт ключи хранилища. Префикс объектов
`jobs/<site>/<job>/<epoch>/<generation>/<assignment>/` разделяет попытки.

Рабочий том проверяется по path/dev/ino. Отключённый или подменённый диск не создаёт
каталог на системном SSD. Файлы попытки: `files/YYYY-MM-DD/<assignment-id>`;
`models/` отдельно. Очистка на старте, при смене UTC-даты и после публикации;
активная работа и ожидание публикации сохраняются.

Упаковка повторяет COPY/ENCODE/SKIP_UPSCALE: без апскейла, X264_EXACT, CRF 0→1,
фактические width/height/bandwidth/mode в манифесте. Профиль сайта не подменяется.
Субтитры на этом этапе не исполняются: при запросе языков шаг SKIPPED, видео
публикуется. Повторы GET/PUT: первая попытка и три паузы 5/15/45 с; 403 обновляет
ссылки без пересборки пакета. После upload.complete аренда закрывается,
AWAITING_PUBLICATION не зависит от жизни устройства. Claim/decision идемпотентны;
release после complete допустим только до claim; PUBLISHING нельзя отменить.

## Проверки

- Windows: `go vet ./...`, `go test ./...`; 16 Node tests, включая прежний WSS-сценарий
  и полный FILE-путь: lavfi 1280×720 → COPY, прямой upload, publication SUCCEEDED,
  очистка попытки.
- Политика: низкое разрешение даёт одну фактическую дорожку; совместимый 720p — COPY;
  403 на GET требует refresh, а не новый пакет; чужой object prefix и неполный grant
  отклоняются; повтор complete/claim/decision; release после complete без дубля;
  REJECTED публикации → FAILED без возврата в очередь.
- Контрактный валидатор и миграция 003 поверх БД этапа 2/3.

Не проверено здесь: физический отрыв док-станции и сон Mac; плеер Desktop/Mobile
на сайте; HTTPS/S3 production; Linux Docker-прогон этого этапа (в тестовый образ
добавлен ffmpeg для следующего прогона). Удаление исходника в S3 после READY
выполняет сайт, не диспетчер.
