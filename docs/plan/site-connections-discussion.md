# Подключения сайтов: согласованные решения и вопросы

Дата: 2026-10-12. Основной источник для следующего обсуждения сервиса.
Реализацию самого сервиса пока не начинаем. Клиент сайта реализуется в serverBreasts/front.

## Согласовано с владельцем

- Сервис главный: работает на компьютере или отдельном сервере и владеет его ресурсами.
- У сервиса собственный интерфейс. Здесь создают сайты, разрешают их доступ, выдают
  отдельные токены, выбирают операции и задают лимиты / приоритеты / очередь каждого сайта.
- Сайт обращается к сервису. Прежний pull с claim/heartbeat отменён; теперь нужен
  доступный сайту адрес сервиса. Сеть и публикацию адреса решаем при реализации сервиса.
- Токен создаёт сервис, оператор вводит его вместе с адресом в админке сайта.
  Адрес сайта — запись подключения / дополнительное ограничение; он сам по себе
  не доказывает подлинность. Проверка доступа основана на отдельном токене сайта.
- Сервис отдаёт каталог разрешённых именно этому сайту операций. Сайт может выключить
  ненужные операции. Решение о разрешении операции и возможности принять задачу у сервиса.
- Одним POST задания сервис проверяет токен, доступ сайта, операцию и квоты, затем
  либо атомарно принимает задачу, либо возвращает понятную причину отказа. Отдельного ping нет.
- Каталог в админке не гарантирует последующий допуск. Новые ограничения действуют
  при каждой отправке, даже если сайт ранее видел операцию в списке.
- У сайта остаётся собственный резерв: определённый отказ / недоступность до передачи
  → выполнить локально, если резерв включён, инструмент установлен и ресурсов хватает.
- Потерянный ответ не равен отказу. Сайт повторяет запрос с тем же ID / опрашивает принятую
  задачу; сервис обеспечивает долговечную идемпотентность. Локальный дубль не запускается.
- После принятия задание можно проверить даже при изменении разрешённых операций.
  Отзыв токена делает состояние для сайта неопределённым; автоматического дубля нет.
- CPU/RAM/диск, параллельность, очередь между сайтами, модели и обновление программы
  управляются на сервисе. Сайт не может менять их через своё подключение.
- Файлы передаются presigned-ссылками; сервис не получает ключи S3 или доступ к БД сайта.
- Первые операции: media.transcribe и media.transcode. media.preview остаётся локальной.

## Контракт, уже реализованный клиентом сайта

Источник: ../../../serverBreasts/docs/instruction/worker-jobs-api.md.

- Authorization: Bearer <site-token> на всех запросах.
- GET /api/site/operations → 200, объект operations с массивом строк-кодов.
- POST /api/site/jobs → id (UUID попытки), type, params, source (url/objectName),
  outputs (name/objectName/uploadUrl), maxOutputBytes.
- Ответ 200/202: тот же id, status ACCEPTED / QUEUED / RUNNING / SUCCEEDED / FAILED / REJECTED.
- REJECTED: code OPERATION_FORBIDDEN / SITE_LIMIT / QUEUE_FULL и другие стабильные коды.
- Первый ответ 401 / 403 / 429 означает отказ до приёма. На повторе после неопределённости
  эти коды не разрешают локальный дубль. 5xx и тайм-аут могут означать потерянный ответ.
- GET /api/site/jobs/{id} → тот же id, status, progress 0…1;
  SUCCEEDED: results (name/objectName/bytes/contentType); FAILED: code, permanent.
- Дедупликация по паре «аутентифицированный сайт + ID», запись принятия до выполнения.
  Повтор того же ID возвращает существующую задачу. Повтор может обновлять временные ссылки
  на те же объекты, но не менять операцию и назначение результата.
- Не выводить токены, presigned-ссылки или текст расшифровки в журналы / ответы других сайтов.
- Сайт хранит снимок подключения принятой попытки: смена адреса / токена в настройках сайта
  не должна терять проверку предыдущей работы.

## Обсудить перед реализацией сервиса

- **Сеть и размещение:** локальная сеть или HTTPS через публичный адрес / VPN;
  как компьютер и выделенный сервер получают доступный сайтам URL.
- **Авторизация интерфейса сервиса:** владелец, доступ к панели, восстановление доступа.
- **Подключения сайтов:** один токен или несколько ключей на сайт, ротация и отзыв;
  как задать дополнительные ограничения адреса/IP за proxy/NAT. Не доверять Origin
  или адресу, переданному самим клиентом, как доказательству личности.
- **Справедливость очереди:** квота на сайт, приоритеты, лимиты ожидания / размера файлов /
  длительности, как один сайт не вытесняет остальных. Конкретные значения пока не выбраны.
- **Операции:** параметры и результаты каждого типа, версии схем, проверка возможностей
  конкретной машины, доступные модели и инструменты. Не принимать произвольные команды ОС.
- **Идемпотентность и хранение:** база / журнал приёма, атомарность принятия,
  восстановление после падения, срок хранения ID и результатов. Срок должен покрывать
  восстановление сайта; нельзя забывать ID и повторно исполнять давнюю попытку.
- **Отмена / неопределённость:** как оператор безопасно отменяет принятую задачу и
  подтверждает, что локальный резерв можно запускать. До подтверждения сайт не дублирует работу.
- **Файлы и ожидание:** срок presigned-ссылок 20 минут по умолчанию на сайте;
  скачивание при приёме или механизм обновления ссылок для долгой очереди.
  Проверить целевые URL, размеры, временные файлы и очистку.
- **Отключение сайта во время работы:** завершить принятую задачу или отменить;
  как сайт с отозванным токеном получает окончательный статус без повторного выполнения.
- **Установка и обновление:** нативный launchd на Mac, сервис ОС на выделенном сервере,
  подписанные релизы / откат и обновление только в безопасный момент; сайт этим не управляет.
- **Журнал и диагностика:** интерфейс ошибок на сервисе, срок хранения,
  доступ сайта только к собственным результатам и состояниям.
