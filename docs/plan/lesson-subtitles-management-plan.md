## Исходное состояние

`media.subtitles` есть в contracts/v2, источник существующего примера `job-subtitles.json` — видео с `speech.sourceLanguage` и `includeOriginal`. `internal/dispatcher/scheduler.go` проверяет RecognitionLanguages даже для этой операции. Простого выбора модели перевода недостаточно: требуется отдельное описание VTT-входа, маршрутизация и ветка исполнения без ASR.

Точки реализации: `contracts/build_contracts.py`, `contracts/v2/`, fixtures, `internal/dispatcher/{protocol,scheduler,catalog,transfer}.go`, `processor/src/{executor,speech,speech-worker}.ts` и связанные capability/model-resolution модули. Точные границы проверить при старте этапа. Контракт генерировать штатным генератором и валидировать, не править только производный JSON.

### Этап 1 — Протокол и capabilities Worker

`Субтитры: создание, перевод и замена языков — этап 1 (Worker)`

- [x] Вместе с Backend утвердить совместимое расширение `media.subtitles` с явным различием video-recognition и subtitle-translation; если расширение несовместимо, определить версию и миграцию до реализации.
- [x] VTT-вход: неизменяемый файловый источник с размером/хешем/версией, явным языком и целевыми языками; выход — VTT по каждому целевому языку. Автоопределение и перевод на язык источника не допускаются.
- [x] В каталоге различать возможности перевода VTT и распознавания речи, языковые направления и ограничения входа; старые потребители не должны принимать VTT-вход за поддерживаемый video-вход.
- [x] Планировщик/резолвер требуют только подходящую модель перевода для VTT-ветки, не требуют RecognitionLanguages/ASR и видеокодировщик. Старый video-путь сохраняется.
- [x] Обновить генератор схем, OpenAPI, нормативный protocol/states, valid/invalid fixtures и инструкцию интеграции. Зафиксировать пределы размера/реплик, таймауты и диагностику неверного входа.

### Этап 2 — Исполнение перевода готовых субтитров

`Субтитры: создание, перевод и замена языков — этап 2 (Worker)`

- [x] Реализовать отдельную ветку executor: получить и проверить VTT → разобрать реплики → переводить только текст → собрать/валидировать VTT → опубликовать артефакты.
- [x] Не скачивать видео и не запускать FFmpeg извлечения аудио, ASR, автоопределение, HLS. В логах/метриках различать стадии и тип входа.
- [x] Сохранить число, порядок, идентификаторы, тайминги и cue settings; корректно обработать переносы и допустимую VTT-разметку/служебные блоки. Точный поддерживаемый набор закрепить fixtures; неизвестные конструкции не удалять молча.
- [x] Модель переводит содержимое реплик с контекстом и устойчивыми ID; не поручать модели сочинять целиком VTT с таймингами. Потерю/слияние/перестановку ID считать ошибкой и ограниченно повторять, не публиковать повреждённый файл.
- [x] Подбирать размер батчей под ограничения модели; проверять непустой текст, полноту и валидность каждого языка. Текст субтитров считать данными, а не инструкциями executor/модели.
- [x] Исходную дорожку не перезаписывать. Для результата использовать существующие безопасные manifests/transfer с уникальной принадлежностью job/attempt; язык, путь, формат и контрольная сумма проверяются.

## Границы ответственности

Worker преобразует входной снимок в артефакты. Разрешение замены, блокировки урока, выбор активного файла и защита продуктовых версий принадлежат Backend. Панель воркера меняется только при необходимости показать capability/стадию; самостоятельный редактор субтитров не нужен.
