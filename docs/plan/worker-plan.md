# План реализации диспетчера и обработчиков

Дата: 2026-10-13. Код не начат. Это рабочий план реализации после обсуждения,
а не инструкция запуска готового продукта. Чекбоксы отмечают выполненную работу,
не только согласованное требование. План не запускает развёртывание/изменения сайтов.

Согласованные технологии: Go-диспетчер, Node.js + TypeScript-обработчики.
Начальные проектные варианты: SQLite с одним активным диспетчером, WSS-канал устройств,
статическая общая панель. Проверяем их в этапах 1–2; это не готовые API или результаты замеров.

## Порядок и границы первой версии

| Этап | Зависит от | Результат |
| --- | --- | --- |
| 1. Аудит и контракт | Документы требований | Отчёт сайта, схемы API, модель состояния, задания для соседних репозиториев |
| 2. Диспетчер | 1 | Приём и долговечная очередь, токены, атомарное назначение |
| 3. Обработчик и связь | 1–2 | Windows/macOS/Linux, reconnect, права исполнения, тестовый исполнитель |
| 4. Хранилище и видео | 2–3 + изменения сайта | Первый полный путь от загрузки до готового видео |
| 5. Модели, аудио и субтитры | 3–4 + каталог моделей | Расшифровка/переводы, частичные результаты и ручное дополнение |
| 6. Общая панель | API 2–5; можно начинать раньше | Управление сайтами, устройствами, моделями и аккаунтами |
| 7. Поставка и эксплуатация | 2–6 | Контейнер/установщики, backup, update/rollback, диагностика |
| 8. Приёмка | 4–7 | Проверенный запуск и инструкции с реальными командами |

Первая версия включает все три ОС; Windows/Mac проверяем на доступных машинах,
Linux — в отдельном тестовом окружении. Новые модели не нужны для проверки основного
видеопути. Начать аудио/субтитры можно после готовности контроля процессов и протокола,
не ожидая завершения оформления всей панели.

## Этап 1 — аудит интеграции и контракт

- [ ] Передать site-backend-readiness.md агенту бэкенда сайта курсов; получить отчёт
  «код / конфигурация / runtime» с подтверждениями, блокерами и задачами фронта.
  Отсутствие готового диспетчера отделять от готовности существующей реализации.
- [ ] Уточнить полный видеопуть курса/урока, не только отдельный handler; существующий
  резерв/политику COPY / ENCODE / SKIP_UPSCALE использовать без повторного изобретения.
- [ ] Создать contracts/: версионированные HTTP-схемы, сообщения устройств и общие fixtures.
  Сохранить совместимый базовый operations/jobs или описать явную миграцию клиента.
- [ ] Спроектировать состояния задания, шагов, назначения, передачи и публикации;
  ошибка дополнительных операций не удаляет успешное видео/дорожки.
- [ ] Спроектировать атомарное назначение одному устройству: ack, срок исполнения,
  продление, отмена, reconnect/reconcile, изолированные поколения выходных объектов.
- [ ] Описать каталог возможностей/языков, профиль результата сайта, свежие ссылки,
  динамический перечень HLS, подтверждение публикации, безопасный резерв сайта.
- [ ] Выбрать интервалы служебных сообщений, веса очереди, правила повторов и очистки,
  срок ID-дедупликации отдельно от истории. Зафиксировать как технические решения.
- [ ] Составить связанные задачи serverBreasts/front: новые DTO/поллер/публикация/уведомления,
  ручной ввод и дорожки. В этом репозитории соседние приложения не переписывать.

Готово: схемы и переходы согласованы между участниками, выявлены несовместимости
фиксированных outputs/ZIP и назначены доработки. Можно писать ядро без ожидания замеров Mac.

## Этап 2 — компактный диспетчер

- [ ] Go-приложение, миграции SQLite, один активный экземпляр, постоянный том.
- [ ] Сайты/операции/приоритеты, отдельные токены сайтов и устройств, выпуск/отзыв,
  изоляция доступа; хешировать проверяемые токены и не выводить их в журнал.
- [ ] Атомарный приём и дедупликация «сайт + UUID»: принятие записать до исполнения,
  повтор запроса возвращает существующую работу даже после потери ответа.
- [ ] Долговечные очередь/назначения/метаданные, восстановление после restart и crash.
- [ ] Справедливый планировщик по сайтам и возможностям устройств: высокий приоритет
  получает больше запусков, остальные продвигаются. Количественные квоты сайтов пока не вводить.
- [ ] Записывать историю/ошибки 30 дней по умолчанию с настройкой, сохранять активные
  задачи и компактную дедупликацию отдельно. Не хранить медиа или модели.
- [ ] Измерить RAM/CPU/размер контейнера при ожидаемом числе подключений/заданий;
  целевой бюджет 128–256 МБ не считать доказанным до замера.

Проверка: повтор приёма, restart, два одновременных назначения и два сайта не создают
новой работы с тем же ID, не публикуют чужой результат и не блокируют низкий приоритет.

## Этап 3 — программа обработки и постоянное соединение

- [ ] Node.js + TypeScript: общий протокол/состояние, платформенные адаптеры,
  безопасный запуск/остановка дерева процессов, тестовый исполнитель до тяжёлых моделей.
- [ ] Исходящий постоянный канал к диспетчеру по токену устройства; сообщения
  характеристик/возможностей/нагрузки, назначения/ack, прогресса и продления.
- [ ] На переподключении сверять активные попытки, не перезапускать задачу вслепую.
- [ ] Две минуты без связи — настраиваемый срок: истечение прежнего права,
  остановка старого исполнителя, переназначение совместимому устройству.
  Старое сообщение/upload не изменяет опубликованный результат новой попытки.
- [ ] Отдельно доступность и продвижение: подозрительное отсутствие активности
  проверяется до остановки, сроки по операциям определить замерами.
- [ ] CPU/RAM/занятость рабочего диска ≥ 80% — новые работы ждут;
  учитывать абсолютные потребности, ускоритель, память/подкачку и устойчивое снижение.
- [ ] Автопараллельность с ручным верхним пределом, локальный резерв ресурсов.
- [ ] 10 минут ожидания — порог проверки задержки, не дедлайн и не автоматический резерв.

Проверка: Mac/Windows/тестовый Linux подключаются, отключение/сон/restart не даёт
новой действующей попытки старому исполнителю. Отдельно проверить потери/задержки ack.

## Этап 4 — файлы и полный видеопуть

- [ ] Очередь хранит записи, скачать исходник ближе к исполнению; обновлять presigned
  для той же попытки. Не выдавать S3-ключи обработчику и не проксировать медиа диспетчером.
- [ ] Настраиваемая рабочая папка и внешний диск, проверка тома/свободного места;
  отключённый диск → ожидание без записи на внутренний SSD.
- [ ] files/YYYY-MM-DD/<attempt-id>, модели отдельно. Очистка после успеха,
  при смене даты, старте и ежедневно; сохранять активную работу и незавершённую передачу.
- [ ] Перенести правила анализа/видеоупаковки сайта, передавать полный профиль результата;
  фактические качества и пропуск апскейла сохраняются. Запрещена молчаливая подмена профиля.
- [ ] Динамический перечень файлов → проверка и ссылки сайта → upload обработчиком
  прямо в хранилище. Объекты разных попыток разделены, число/размер/пути проверяются.
- [ ] Сервер сайта проверяет комплектность, публикует и подтверждает; повтор upload/commit
  идемпотентен. Исходник удалять после подтверждения, опубликованный пакет сохранять.
- [ ] Существующий резерв видео на сайте включать только по подтверждённому безопасному
  переходу; после неопределённости не запускать дубль. Отсутствие другого устройства
  не равно праву сайта немедленно забрать уже принятую работу.
- [ ] Временные сбои передачи повторять до трёх раз с выбранными паузами, готовый
  результат не пересоздавать из-за одного сбоя upload.
- [ ] Окончательная ошибка основной операции: код/причина, статус сайта, удаление
  исходника/частичных файлов и уведомление. Отмена отдельно, не затрагивать чужие результаты.

Проверка: полный путь тестового видео, потеря upload/подтверждения, COPY без пересжатия,
низкое разрешение, отказ/отмена, смена даты, отключение SSD; плеер Desktop/Mobile.

## Этап 5 — каталог моделей, аудио и субтитры

- [ ] Выбрать и закрепить конкретные исполнители/модели, лицензии, форматы и версии.
  Языки брать из проверенного описания модели, а не фиксировать русский/английский.
- [ ] Каталог по ОС/CPU/ускорителю/RAM/VRAM: назначение, языки/направления перевода,
  размер и контроль загрузки. Наличие модели не равно готовности её исполнителя.
- [ ] Команды установки/активации/удаления на выбранном устройстве, скачивание туда,
  прогресс, свободное место и защита активных моделей. Вне каталога — отдельный механизм.
- [ ] Аудио → сплошной текст языка оригинала, без перевода/таймкодов/говорящих;
  режимы быстрее/качественнее/автоматически по ресурсам.
- [ ] Видео: единая пользовательская задача создания отдельных дорожек для плеера,
  внутренние этапы распознавания/таймкодов/перевода на выбранные доступные языки.
- [ ] Сохранять видео/успешные дорожки при ошибке дополнительного шага;
  причины по операциям/языкам возвращать сайту, предусмотреть повтор только нужного шага.
- [ ] Без дополнительного резерва на сайте — ручной текст/загрузка субтитров;
  основная обработка видео не блокируется. media.preview остаётся локальной на сайте.

Проверка: разные языки и модели, неподдерживаемое направление, текст аудио,
частичный успех, ручная дорожка и выбор языка плеером. Качество/скорость измеряются
отдельно, замер Windows не обещает производительность Mac.

## Этап 6 — общая панель

- [ ] Владелец/операторы и разрешения, сессии, журнал действий; срок журнала выбрать.
- [ ] Сайты/токены/операции/приоритеты, устройства/токены/возможности/нагрузка,
  очередь/этапы/история/ошибки, отмена одного/всех заданий сайта.
- [ ] Отключение сайта прекращает новые приёмы, текущие завершаются; немедленная отмена отдельно.
- [ ] Выбор устройства → совместимые модели → установка/удаление и прогресс.
- [ ] Настройки рабочего диска/порогов/параллельности, пауза, автозапуск, update;
  показать подтверждённую устройством конфигурацию, а не только желаемую.
- [ ] Первоначальная инициализация владельца и серверная команда сброса пароля без почты.

Проверка: роль оператора не получает права владельца или секреты сайтов/устройств;
неподключённая машина не выглядит настроенной успешно.

## Этап 7 — поставка и эксплуатация

- [ ] Dockerfile/Compose, постоянные тома, health/readiness, HTTPS/proxy с WSS,
  перезапуск, ограниченные логи и проверенные лимиты на основном сервере сайта.
- [ ] Пакеты обработчиков для Windows/macOS/Linux, закреплённый Node LTS/зависимости,
  проверка среды и установка автозапуска с возможностью отключения.
- [ ] Подготовить backup/restore диспетчера: суточный согласованный снимок,
  локально + внешнее S3, ориентир семь копий, отдельный бакет/префикс.
  Адаптировать существующий механизм PostgreSQL backup сайта к выбранной БД.
- [ ] Restore в отдельной среде, сверка поколений/активных работ, защита от старых результатов;
  резервная копия не обещает вернуть все изменения после момента снимка.
- [ ] Обновление владельцем из панели после текущих работ; dispatcher maintenance,
  сохранение очереди и секретов, snapshot перед миграцией, совместимый откат/restore.
- [ ] Дополнить инструкции точными командами поставленных CLI/образов и диагностикой,
  а не выдумывать команды до существования соответствующего кода.

Проверка: новый сервер/устройство разворачиваются по инструкции; update/rollback,
reset-password и restore проверены в тестовой среде.

## Этап 8 — совместная приёмка и готовность к запуску

- [ ] Проверить аудит и завершить необходимые задачи бэкенда/фронта сайта.
- [ ] Полный путь: сайт → диспетчер → устройство → хранилище → публикация/плеер.
- [ ] Два устройства/несколько сайтов: приоритеты, перегрузка, конкурентное назначение,
  отказ диспетчера, потеря связи/ответа, пауза/сон/перезапуск и отмена.
- [ ] Проверить поздний результат старой попытки, истёкшие ссылки, частичный upload,
  неполный пакет, частичный успех субтитров и безопасный резерв видео.
- [ ] Замерить RAM/CPU диспетчера и аппаратные возможности обработчиков;
  выбрать реальные пределы и отдельно отметить непроверенное оборудование.
- [ ] Проверить очистку/историю/дедупликацию, внешний SSD, backup и восстановление.
- [ ] Подготовить отчёт «готово / блокеры / ограничения» и инструкции для пользователя.

Первый production-запуск выполняется после этой приёмки как отдельное действие.
Документы плана не являются доказательством готовности существующего production-сервера.
