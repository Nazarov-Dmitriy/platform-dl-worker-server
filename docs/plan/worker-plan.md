# Обработчик: каркас, расшифровка, транскодирование

Дата: 2026-10-12. Код не начат. Здесь — только работы по программе обработчика.
Серверная часть и контракт API: `serverBreasts/docs/plan/media-workers-plan.md`.
Этапы соответствуют этапам бэка и выполняются вместе с ними.

## Зафиксированные решения

Node (TypeScript), запуск нативным процессом под `launchd`, без Docker на Apple Silicon.
Тяжёлые инструменты (`ffmpeg`, распознавание речи) — внешние процессы, ставятся и обновляются
отдельно от кода обработчика. Зависимостей у программы минимум: по возможности только
стандартная библиотека Node, чтобы на машине обработчика не требовался `npm install`.

Транспорт только исходящий: `claim` с длинным ожиданием, `heartbeat` с прогрессом
и свободными слотами, затем `complete` или `fail`. Входящий порт не открывается.
Файлы читаются и записываются по presigned-ссылкам из наряда; доступа к базе
и ключам хранилища у обработчика нет.

Обработчик не медийный: тип задачи несёт доменный префикс. Возможности объявляются
в `claim`, новый тип задач добавляется строкой в список и своим исполнителем.

Конфигурация — локальный файл вне репозитория (`config.json`, в репозитории только
`config.example.json`): базовый URL, токен, возможности, `maxParallel`, уровень журнала,
параметры обновления. Токен и подписанные ссылки не попадают в журнал.

## Этап 1 — цикл задачи, конфигурация, журнал и запуск

`Обработчик: каркас, расшифровка, транскодирование — этап 1`

- [ ] Цикл работы: `claim` с длинным ожиданием, повтор при 204, пауза и повтор
  с увеличением задержки при недоступности сервера.
- [ ] Выполнение задачи `media.preview`: чтение исходника по presigned-ссылке,
  один вызов `ffmpeg`, запись результата по ссылке на запись, `complete`.
- [ ] `heartbeat` с прогрессом по расписанию из наряда; реакция на `cancel`
  и на 409 — прекращение работы и удаление временных файлов.
- [ ] Классификация ошибок: постоянные (`SOURCE_UNREADABLE`, `UNSUPPORTED_FORMAT`,
  `DURATION_EXCEEDED`, `PARAMS_INVALID`) и временные (`TOOL_CRASHED`, `DOWNLOAD_FAILED`,
  `UPLOAD_FAILED`, `DISK_FULL`, `TIMEOUT`, `CANCELLED`); `fail` с кодом, флагом
  и обрезанным хвостом вывода инструмента.
- [ ] Конфигурация из локального файла с проверкой при старте: отсутствующий токен
  или базовый URL — остановка с понятным сообщением, а не бесконечные попытки.
- [ ] Соблюдение `maxParallel` (по умолчанию 1) и файла-признака занятости для обновления.
- [ ] Журнал: построчные структурированные записи в файл, ротация по дням,
  ограничение глубины истории, подробный уровень параметром конфигурации.
  В записи не попадают токен, подписанные ссылки и текст расшифровки.
- [ ] Отправка записей уровня предупреждения и ошибки на сервер батчами;
  при 429 и при недоступности сервера работа продолжается, записи остаются локально.
- [ ] Очистка временных файлов при любом исходе задачи, включая падение процесса.
- [ ] Запуск под `launchd` (`ru.dmitriy.worker`) с автоподъёмом после падения
  и после перезагрузки; инструкция по установке в README.
- [ ] Автообновление: сверка тегов репозитория по таймеру, переход на новый тег
  только при отсутствии активной задачи, перезапуск агента. Обновление по ветке не применяется.
- [ ] Версия программы передаётся в `claim` и `heartbeat`.
- [ ] Проверка связи без работы: `claim` с `freeSlots: 0`.

## Этап 2 — расшифровка аудио

`Обработчик: каркас, расшифровка, транскодирование — этап 2`

- [ ] Исполнитель типа `media.transcribe`: вызов распознавания как внешнего процесса
  с ускорением на Apple Silicon.
- [ ] Модель загружается на задачу и освобождается после неё; постоянная резидентность
  не требуется. Путь к модели и выбор модели — в конфигурации.
- [ ] Прогресс по ходу распознавания в `heartbeat`, чтобы медленная задача
  не считалась потерей обработчика.
- [ ] Замеры на реальном русском аудио: скорость, память, качество; результат замеров
  определяет выбор модели и ограничение длительности.
- [ ] Текст результата не пишется в журнал.

## Этап 3 — транскодирование видео

`Обработчик: каркас, расшифровка, транскодирование — этап 3`

- [ ] Исполнитель типа `media.transcode`: подготовка видео через `ffmpeg`
  с аппаратным кодированием VideoToolbox, несколько выходных файлов из `outputs` наряда.
- [ ] Локальные лимиты: ограничение потоков `ffmpeg`, одна тяжёлая задача за раз,
  проверка свободного места перед началом.
- [ ] Поведение при нехватке места на диске: временная ошибка `DISK_FULL`
  без попытки продолжить.
