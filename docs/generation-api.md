# Генерация изображений: интеграция сайта

Реализовано локально 2026-11-06. Для использования нужны обновлённые диспетчер и worker. Установленное приложение пока не заменено по договорённости с владельцем. Реальные генерации на весах FLUX/Z-Image и замеры памяти ещё требуют приёмки.

## Разрешение и доступные модели

В панели «Сайты» включите операцию «Генерация изображений» для нужного сайта. Сайт обращается с обычным site bearer token к `GET /api/v2/site/generation/models`.

Ответ: `{ "protocolVersion": "2.0", "models": [...] }`. Список содержит только активированные модели подключённых устройств, готовых принять работу: учитываются пауза, ресурсы, свободные слоты и стабильность подключения. Занятые и недоступные модели скрыты. Один профиль на нескольких устройствах возвращается один раз. При отсутствии готовых устройств список пуст; без разрешения — `403 OPERATION_FORBIDDEN`.

Каждая модель содержит `id`, `revision`, `profileRevision`, `name`, `description`, необязательное `parameterCount`, `acceptsReference` и `parameters`. Поле параметра содержит `key`, `label`, `type`, `required` и при необходимости `default`, `minimum`, `maximum`, `step`, `maxLength`, `options`. Сайт строит форму по выбранному профилю и передаёт значения по ключам. Значения по умолчанию сайт должен подставить в форму; обязательные поля должны присутствовать в запросе.

Диспетчер проверяет общий контракт и маршрутизирует задания. Названия конкретных моделей, их запуск и поддерживаемые параметры определяет worker. Два устройства могут иметь разные модели. Если выбранная модель есть только на помощнике, задание получает помощник; при одинаковой модели приоритет сохраняется за основным устройством.

## Задание

Отправьте обычный `POST /api/v2/site/jobs` с ключом идемпотентности по существующему контракту. Пример тела:

```json
{
  "protocolVersion": "2.0",
  "id": "11111111-1111-4111-8111-111111111111",
  "type": "media.generate",
  "params": {
    "modelId": "значение id из списка",
    "modelRevision": "значение revision из списка",
    "profileRevision": "значение profileRevision из списка",
    "inputs": { "prompt": "Лес на рассвете", "width": 1024, "height": 1024, "seed": 42 }
  },
  "maxOutputBytes": 16777216,
  "maxDurationSeconds": 600
}
```

Для текста `source` отсутствует. Если `acceptsReference: true`, можно передать один `source` типа `FILE` по существующему механизму исходных файлов: PNG/JPEG, максимум 32 МиБ, стороны до 4096 пикселей и площадь до 16 мегапикселей. Пример метаданных — [fixture референса](../contracts/fixtures/valid/job-generation-reference.json). Передаваемые размер и SHA-256 проверяются загрузчиком.

Если выбранный профиль исчез между получением списка и отправкой, сервер возвращает `409 MODEL_UNAVAILABLE`: обновите список и предложите выбор заново. Модель автоматически не подменяется. Неизвестные поля, неправильные типы, пределы или референс для модели без такой возможности дают `400 INVALID_GENERATION_PARAMETERS`.

Прогресс, отмена, аренда выполнения и публикация результата используют существующий протокол заданий. Успешный результат — один файл `IMAGE` с `contentType: image/png` и успешным шагом `generation`. Файл проходит обычную загрузку и подтверждение публикации.

## Текущие профили worker

| Модель | Вход | Размер | Seed |
| --- | --- | --- | --- |
| FLUX.2 Klein 4B Q4 | Описание, необязательно один референс | Каждая сторона: 512, 768 или 1024 | −1 или 0…4294967295 |
| Z-Image-Turbo Q4 | Описание | Каждая сторона: 512, 768 или 1024 | −1 или 0…4294967295 |

Описание обязательно, до 4000 символов. Выдаётся одно изображение. Число шагов пока закреплено в профиле worker: 4 для FLUX, 8 для Z-Image. Полные Safetensors-пакеты остаются в каталоге для установки, но текущим executor не активируются. На одном worker активна одна модель генерации; во время её выполнения другая генерация на этом worker не принимается.

Исполнение: stable-diffusion.cpp. В настройках обработки доступны «Автоматически», «Процессор» и «Видеокарта». Авто выбирает CUDA/Metal, при отсутствии ускорителя — CPU. Режим видеокарты не переходит на CPU молча; кодировщик и VAE в нём остаются на CPU. Режим процессора использует RAM и общий бюджет CPU-потоков, разделённый между параллельными заданиями. Изменения применяются к новым заданиям. После задания процесс движка завершается. Требования памяти предварительные; определение GPU и наличие файлов не подтверждают успешную загрузку весов. Официальная закреплённая сборка Metal требует macOS 26+.

Контракты: [OpenAPI](../contracts/v2/openapi.json), [JSON Schema](../contracts/v2/protocol.schema.json).

## Исправление продления задания — 2026-11-06

Во время генерации worker передаёт этап `GENERATING`. Диспетчер должен принимать
его не только в JSON Schema, но и в проверке `Store.Renew`; иначе продление
отклоняется с INVALID_STATUS, аренда истекает и задание может назначаться повторно.
Исправление проверено тестом продления и отмены; необходимо обновить запущенный
диспетчер. На стороне сайта отмена v2 должна включать стабильный `requestId`.
Подробности проверки: [image-generation-models.md](testing/image-generation-models.md#продление-generating-и-отмена--2026-11-06).
