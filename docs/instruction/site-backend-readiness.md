# Проверка готовности бэкенда сайта к внешней обработке

Дата: 2026-10-13. Этот документ можно целиком передать агенту в репозитории сайта,
в том числе сайта курсов. Задача — аудит и список доработок, не развёртывание.
Диспетчер и обработчики реализованы и проверены локально; совместная интеграция
и production-окружение проверяются отдельно. Отсутствие развёрнутого диспетчера
не означает неисправность кода сайта. Для реализации после аудита использовать
[универсальную инструкцию интеграции](service-integration.md).

## Готовое задание для агента

> Проверь готовность бэкенда этого сайта по приведённому ниже чеклисту. Прочитай местные
> AGENTS.md / правила проекта. Найди существующую реализацию, настройки, миграции и тесты.
> Для каждого пункта укажи: готово в коде / требует доработки / требует настройки /
> не проверено в окружении / неприменимо, со ссылкой на файл и объяснением.
> Отдельно проверь код и фактическую конфигурацию развёрнутого сервера, если доступна.
> Не считай значения по умолчанию доказательством действующих настроек.
> Не печатай секреты, токены и полные presigned-ссылки. Не запускай реальные пользовательские
> задания, удаления, миграции, смену настроек или production restore ради проверки.
> Если живой проверки нет, явно отметь это. Выполни применимые проверки проекта на
> тестовых данных, если они не затрагивают рабочие данные. Не реализуй отсутствующий
> протокол по догадке: перечисли недостающие части и зависимости от диспетчера.
> Подготовь отчёт готовности и приоритетный список доработок. Исправления/деплой — отдельный этап.

## Архитектура, на которую проверяется сайт

- На сервере отдельный компактный диспетчер Go: сайты, аккаунты, токены, общая очередь,
  приоритеты, устройства. SQLite — начальный проектный вариант, один активный диспетчер.
- Сайт подключается к HTTPS-поддомену диспетчера отдельным токеном сайта.
  Фронтенд работает через свой бэкенд, не получает секрет подключения.
- Обработчики Node.js + TypeScript на Windows/macOS/Linux сами поддерживают исходящее
  соединение с диспетчером со своими токенами устройств. Диспетчер назначает каждую
  попытку одному устройству, учитывает возможности/нагрузку.
- У сайта остаётся долговечная собственная задача. Общая очередь исполнения и назначение
  устройств находятся у диспетчера. Сайт не выбирает устройство самостоятельно.
- Исходники и результаты передаются обработчиком напрямую через хранилище сайта,
  по временным ссылкам. Диспетчер не хранит видео и не пересылает медиапакеты.
- Резерв сайта выполняет основную обработку видео. Распознавание и перевод на сервере
  сайта для первой версии не обязательны: при недоступности дополнительных операций
  предложить ручной текст или загрузку готовых субтитров.
- Аудио → сплошной текст языка оригинала. Видео → обработка и отдельные дорожки
  субтитров, в том числе выбранные переводы; ошибки дополнительных шагов не удаляют видео.

## A. Существующий контракт и настройки

- [ ] Есть режим SERVER / EXTERNAL, адрес диспетчера, токен, переключатель резерва,
  выбранные операции, проверка подключения и актуальный каталог.
- [ ] Токен зашифрован/защищён на сервере, не возвращается браузеру и не попадает в логи.
  Смена адреса/токена не теряет проверку ранее принятой работы.
- [ ] HTTP-клиент имеет тайм-ауты, ограничение тела ответа, проверку адреса и TLS.
  HTTP разрешён только для согласованных локальных тестов.
- [ ] Найдены фактические запросы и DTO. Текущий исходный контракт:
  GET /api/site/operations → operations (массив кодов);
  POST /api/site/jobs → id, type, params, source, outputs, maxOutputBytes;
  GET /api/site/jobs/{id} → id, status, progress, results или ошибка.
- [ ] Поддержаны статусы ACCEPTED / QUEUED / RUNNING / SUCCEEDED / FAILED / REJECTED,
  проверка ID и результатов. Новые статусы отмены/частичного успеха ещё должны быть
  описаны в версии протокола; не считать их существующими по этому чеклисту.
- [ ] Есть версия протокола или план перехода с фиксированных outputs на расширенный
  каталог языков/направлений, динамические HLS-файлы и дополнительные результаты.

## B. Очередь сайта и исключение дублей

- [ ] Собственная задача сохраняется до отправки; UUID попытки стабилен при повторах
  после потерянного ответа. Принятая/неопределённая попытка хранится между перезапусками.
- [ ] Определённый отказ до приёма отличается от тайм-аута/5xx после отправки.
  При неопределённости повторяют тот же ID / опрашивают, не запускают локальный дубль.
- [ ] 10 минут ожидания — настраиваемый порог проверки задержки, без автоматического
  резерва, если диспетчер отвечает и работа продвигается.
- [ ] Две минуты без связи устройства — правило диспетчера, а не повод сайта
  самостоятельно украсть принятую работу. Переключение на резерв сайта требует
  подтверждённого освобождения/передачи права, которое ещё нужно реализовать в протоколе.
- [ ] Отмена, отключение сайта, отзыв токена и потеря связи имеют понятные состояния;
  нельзя принимать старый результат после отмены/новой попытки.

## C. Основная обработка видео и резерв

- [ ] Основной видеопуть реально использует общий упаковщик и настройки сайта.
  Проверять не только job handler, но создание/замену видео урока или курса до публикации.
- [ ] FFmpeg и FFprobe установлены ВНУТРИ нужного runtime/контейнера, доступны процессу;
  поддерживаются требуемые кодеки, рабочая папка доступна, RAM/диск/процессы ограничены.
- [ ] Сохраняется существующая политика COPY / ENCODE / SKIP_UPSCALE:
  совместимый компактный исходник не пересжимается без необходимости;
  перекодирование имеет потолок битрейта, апскейла нет, плеер получает фактические качества.
- [ ] Внешнее задание передаёт полный снимок запрошенного профиля, а не только «720p»:
  выбранные качества, параметры кодирования/упаковки и правила копирования.
  Изменение настроек после отправки не меняет смысл уже принятой попытки.
- [ ] При недоступности обработчиков резерв видео работает на сайте и не подменяет
  запрошенное качество по собственной инициативе. Не требовать установки моделей на сервер сайта.
- [ ] Есть применимые тесты политики/FFmpeg. Реальное воспроизведение, звук,
  перемотка и выбор качества проверяются на тестовом видео отдельно.

## D. Хранилище и протокол публикации

- [ ] Исходник хранится до окончательного результата. Сайт умеет выдавать временные
  GET/PUT-ссылки; обработчики не получают постоянные S3-ключи.
- [ ] Ссылки обновляются для той же попытки/объектов: очередь может длиться дольше TTL.
  Существующий ориентир TTL 20 минут не гарантирует, что ссылка доживёт до исполнения.
- [ ] Для готового HLS-пакета сайт принимает перечень файлов и выдаёт ссылки на
  сегменты/плейлисты/дорожки. Выдача ограничена сайтом, заданием и действующей попыткой.
- [ ] Результаты разных попыток имеют разные назначения в хранилище. Старый PUT
  не может перезаписать опубликованный результат новой попытки.
- [ ] Проверяются реальные наличие, размер и согласованный состав результатов;
  плейлисты ссылаются только на разрешённые объекты этого пакета. Контрольные суммы
  использовать по согласованному контракту, не полагаться на произвольный ETag как хеш файла.
- [ ] Публикация логически атомарна: неполный пакет не показывается как готовый.
  После проверки сервер подтверждает приём, только тогда обработчик очищает результат.
- [ ] Проверить несовпадение с текущим ZIP/фиксированными outputs. Это доработка,
  а не уже готовая возможность. Нужен переход существующих потребителей результата.
- [ ] Очистка: успех → удалить исходник, сохранить опубликованный пакет;
  окончательная ошибка основной обработки → удалить исходник/незавершённый пакет;
  ошибка дополнительной операции → сохранить основное видео/успешные дорожки.
  Не удалить готовый объект, если исходник был использован как результат без копии.

## E. Расшифровка, субтитры и пользовательские состояния

- [ ] Аудио принимает сплошной текст оригинала, без обязательных таймкодов/перевода.
- [ ] Каталог языков определяется установленными моделями, отдельно распознавание
  и направления перевода; бэкенд отдаёт его фронтенду. Недоступность каталога понятна.
- [ ] Готовые отдельные субтитры прикрепляются к видео, язык доступен плееру;
  есть ручная загрузка и проверки разрешённого формата/размера/содержимого.
- [ ] При частичном результате сохраняются видео/успешные дорожки; пользователь получает
  список невыполненных операций/языков и причины. Не требовать полного пересоздания видео.
- [ ] Если дополнительная операция недоступна, UI предлагает ручной ввод текста/субтитров.
  Это не окончательная ошибка основной обработки.
- [ ] Есть состояние ожидания, прогресс/этап, отмена, окончательная ошибка и уведомление
  пользователя. Если фронт в другом репозитории, перечислить его задачи отдельно.

## F. Окружение и эксплуатация

- [ ] Из серверного runtime доступен HTTPS-адрес диспетчера; из обработчиков доступны
  URL хранилища. Доступность проверена в нужной сети, не только с ноутбука разработчика.
- [ ] Миграции таблиц задач/попыток/настроек применены; экземпляры поллера координируются.
- [ ] Настройки проверены по фактическому окружению с замаскированными секретами.
  В исходном serverBreasts полезные имена: MEDIA_FFMPEG_PATH, MEDIA_FFPROBE_PATH,
  MEDIA_FFMPEG_WORK_DIR, JOBS_WORKER_PRESIGN_TTL, JOBS_WORKER_SERVER_MAX_PARALLEL,
  JOBS_WORKER_TRANSCODE_THREADS. Для другого сайта имена могут отличаться.
- [ ] Ротация журналов/временных файлов, место хранилища, собственный backup/restore
  сайта и мониторинг ошибок не конфликтуют с диспетчером.
- [ ] Новая интеграция проверяется на тестовых объектах, не удаляет старые готовые видео
  и не запускает пересжатие существующего каталога автоматически.

## Формат отчёта и критерий запуска

Таблица: пункт | статус | доказательство (файл:строка или безопасный результат проверки)
| необходимая доработка | проверено в runtime? Затем:

1. Готово к режиму основной обработки видео: да / нет / не проверено.
2. Готово к расширенному HLS-протоколу: да / нет, блокирующие пункты.
3. Готово к аудио/субтитрам/частичному результату: по каждой возможности отдельно.
4. Задачи бэкенда, фронтенда, диспетчера и инфраструктуры отдельными списками.
5. Какие тесты выполнены, какие проверки требуют доступного окружения.

Не давать общий ответ «всё готово» по наличию классов. Разрешать поэтапный запуск:
готовая видеоупаковка не означает готовность динамической загрузки или перевода.
