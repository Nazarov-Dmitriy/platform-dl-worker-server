# Установка worker-server без ручной подготовки сертификатов

Нужен только готовый архив. Сертификат и ключ заранее создавать, покупать или
загружать не нужно: установщик сам создаёт их для указанного IP или DNS-имени.
На VPS нужны Docker с Compose v2, Python 3.9+ и OpenSSL.

## Установка

Перенесите архив на VPS, распакуйте в `/tmp/worker-release`. Затем:

```sh
sudo bash /tmp/worker-release/install.sh --host 194.5.79.198
```

Установщик загрузит оба готовых Docker-образа из архива, создаст сертификаты,
владельца и пароль, запустит сервис и проверит TLS. Ничего собирать не нужно.
Панель: `https://194.5.79.198:8090/panel/`.
Порт можно поменять: `--port 8091`. Разрешите этот TCP-порт в firewall провайдера.
Nginx сайта, его `.env` и порты 80/443 установщик не меняет.

Логин: `owner`. Посмотреть первоначальный пароль:

```sh
sudo cat /opt/worker-server/initial-owner-password
```

## Один раз на Mac и Windows

Установка сама создаёт **публичный файл доверия** `/opt/worker-server/device-ca.crt`.
Скопируйте только этот файл на свои компьютеры (например, через SCP).
Приватные ключи из `tls/` и архив переезда на устройства копировать не нужно.

Для панели в браузере импортируйте `device-ca.crt` в доверенные корневые
сертификаты Windows либо в Связку ключей macOS с доверием к SSL.
Это один раз для вашей установки; проверку сертификата отключать не нужно.

Для программы-обработчика положите файл рядом с её `config.json` и добавьте:

```json
{
  "url": "wss://194.5.79.198:8090/api/v2/device/connect",
  "tlsCaFile": "device-ca.crt"
}
```

Это два поля существующего config.json, а не весь конфиг: deviceId и остальные
параметры сохраняются. Обработчик сам прочитает CA из файла и проверит TLS;
настройка работает и при автозапуске, без NODE_EXTRA_CA_CERTS и изменения
системного доверия для Node. Адрес и токен каждого устройства задаются отдельно.
Программа должна быть обновлена до версии с поддержкой tlsCaFile.

При подключении Java-бэкенда сайта частный CA также должен быть добавлен в его
truststore. Установщик не меняет рабочий бэкенд и не включает EXTERNAL автоматически.

## Продление и повторная установка

На VPS с systemd автоматически включается ежедневная проверка сертификата.
За 30 дней до истечения он перевыпускается, собственный nginx делает graceful
reload. Файл доверия на Mac/Windows остаётся прежним. Срок CA — 10 лет, серверного
сертификата — 397 дней. При отсутствии systemd установщик сообщает об этом;
проверку можно запускать вручную или своим планировщиком:

```sh
sudo python3 /opt/worker-server/setup.py --renew-tls --dir /opt/worker-server
```

Повторная установка той же версии сохраняет аккаунты, токены и CA.
Установщик можно повторно запустить из распакованного архива той же командой.
Произвольная замена версии образа поверх базы запрещена: обновление требует
отдельного обслуживания, снимка и проверенного пути миграции.

Если у вас уже есть собственный сертификат, необязательно использовать автосоздание:
`--cert /root/fullchain.pem --key /root/privkey.pem`, при своём CA также `--ca /root/ca.pem`.
Для ручных сертификатов продление остаётся на владельце. Поддомен не обязателен.

## Переезд на другой VPS

1. В панели включите обслуживание и дождитесь завершения назначенных работ.
2. На старом сервере:

   ```sh
   sudo bash /opt/worker-server/export.sh /root/worker-move.tgz
   ```

   Экземпляр остановится. Архив содержит базу, настройки, образы, сертификаты
   и ключи; храните/передавайте его только приватно. Старый экземпляр не запускается
   автоматически, две копии одной базы одновременно работать не должны.
3. Перенесите архив на новый VPS и распакуйте с sudo в `/opt/worker-server`.
4. Запустите:

   ```sh
   sudo bash /opt/worker-server/install.sh --host НОВЫЙ_IP
   ```

   Сертификат для нового IP создастся сам. **CA остаётся прежним**, поэтому
   повторно добавлять доверие на Mac/Windows не требуется. Обновите IP в адресе
   обработчика и настройках сайта, откройте порт у провайдера, проверьте подключение,
   затем выключите обслуживание.

Это перенос полного остановленного состояния. Для отката к старому снимку
используйте штатный restore с новой epoch. Старый VPS не запускайте после начала
обработки новым. При отказе от переезда можно запустить старый экземпляр обратно
через `docker compose up -d` и снять обслуживание.

## Файлы и параметры

Постоянная папка по умолчанию `/opt/worker-server` (`--dir`).

- `data/`: SQLite, очередь, аккаунты и токены; сохраняется при перезапуске.
- `tls/authority/`: секретный ключ собственного CA, каталог 700, ключ 600.
- `tls/fullchain.pem`, `tls/privkey.pem`: серверный сертификат и ключ.
- `device-ca.crt`: публичный файл доверия, разрешено передать своим устройствам.
- `initial-owner-password`: первоначальный пароль, права 600; пароль в .env не записывается.
- `.env`: DISPATCHER_IMAGE (из релиза), PUBLIC_HOST (из --host), PUBLIC_PORT (8090),
  LISTEN_IP (0.0.0.0), OWNER_LOGIN (owner), TLS_MODE (auto, либо manual при --cert/--key).
- `release.env` в архиве: версия и отпечатки готовых образов; после загрузки проверяются.
- `SHA256SUMS`: контрольные суммы поставки; проверка: `sha256sum -c SHA256SUMS`.

Для изолированного теста: `--listen-ip 127.0.0.1 --port 18090 --no-renew-timer`.
Для исходников без образов: `--image <версионированный-образ>`; latest запрещён.
Параметр tlsCaFile обработчика необязателен; путь считается от его config.json.

Готовые архивы сборки находятся в **deploy/releases/**, исходники установки —
в deploy/standalone/. Сборка: `bash deploy/standalone/package.sh`.
GitHub workflow выпускает архив по тегу worker-v* или ручному запуску.

Рабочее использование EXTERNAL включается только после подключения реального
обработчика и проверки отдельного тестового медиафайла по всей цепочке.
