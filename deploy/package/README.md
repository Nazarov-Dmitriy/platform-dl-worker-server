# Worker-server: установка как пакета

## Установка

Распакуйте готовый архив **в ту папку, где хотите держать сервис**. В ней:

```sh
sudo bash worker install
```

Установщик спросит IP/домен, логин и пароль. Вы задаёте пароль сами; искать его
в файлах не нужно. Готовый образ загружается из пакета. TLS, сертификат, база
и аккаунт подготавливаются внутри **одного контейнера**, без отдельного Nginx,
ручных ключей и внешних таймеров. Сервис автоматически поднимается после перезагрузки.

Всё остаётся рядом: **instance/** — данные и настройки вашего сервиса.
Установщик печатает точный путь и ссылку на панель. Никаких переносов в /opt или
распаковок в /tmp команда worker install не выполняет.
Порт по умолчанию 8090; его нужно разрешить в панели провайдера.

Вариант из GitHub вместо готового архива:

```sh
git clone git@github.com:Nazarov-Dmitriy/platform-dl-worker-server.git server-worker
cd server-worker
sudo bash worker install
```

При установке из Git Docker-образ собирается автоматически. Go/Node на VPS не нужны.
Для готового архива сборка не выполняется; Git и доступ к реестру не требуются.
Нужны Docker Engine, Compose v2 и Python 3.9+ на Linux amd64.

## Панель и сертификат

Панель: `https://ВАШ_IP:8090/panel/`. Вход — логин и пароль, заданные при установке.
На первом открытии браузер предупредит, что сертификат установки ему ещё неизвестен.
Для своей установки проверьте адрес сервера. В панели есть кнопка
**«Скачать сертификат для Mac и Windows»**, доступная и на экране входа.
Она скачивает только публичный device-ca.crt, никогда приватный ключ.

На каждом своём компьютере один раз добавьте скачанный сертификат в доверенные
для браузера. Для Node-обработчика положите файл рядом с config.json и укажите
`"tlsCaFile": "device-ca.crt"`. Сертификат проверяется, TLS-проверка не отключается.
Для Java-бэкенда CA добавляется в его truststore отдельно.

Создание серверного сертификата и его продление происходят в контейнере автоматически.
При перезапуске/переезде CA сохраняется в данных, поэтому доверие остаётся прежним.
Серверный сертификат действует 397 дней, за 30 дней до истечения перевыпускается
в процессе без перезапуска контейнера. CA — 10 лет, хранится приватно вместе с базой.

Управление устройствами, моделями и сайтами уже есть в панели. Новый интерфейс
и формы дополнительных настроек обсуждаются отдельно; установки произвольных
расширений и автоматической настройки DNS в этой поставке нет.

## Команды

Из папки пакета:

```sh
sudo bash worker status
sudo bash worker logs
sudo bash worker stop
sudo bash worker start
bash worker where
```

Повторный `worker install` сохраняет аккаунты и токены. Для установки без вопросов
можно передать --host, --login и --password-stdin; пароль не пишется в аргументы.
--port меняет внешний порт, --dir задаёт собственную папку данных,
--listen-ip 127.0.0.1 нужен для изолированного тестирования.

## Переезд

Включите обслуживание в панели и дождитесь завершения назначенных работ.

```sh
sudo bash worker export /root/worker-move.tgz
```

Старый экземпляр остановится. Перенесите полученный архив на новый VPS, распакуйте
с sudo в выбранную папку и выполните там:

```sh
sudo bash worker install --host НОВЫЙ_IP
```

База, аккаунты, CA и токены сохранятся. Пароль заново не задаётся. Старую копию
одновременно не запускайте. Откройте порт, обновите IP в настройках устройств,
проверьте панель, затем снимите обслуживание. Архив переезда содержит секреты:
передавайте его приватно, права файла 600.

Самостоятельный Docker-запуск тоже поддерживается: образу достаточно DISPATCHER_HOST
и постоянного тома /data. Для удобства задайте аккаунт через worker install;
прямой запуск образа без него создаёт owner и пароль в /data/initial-owner-password.

В instance/.env хранятся DISPATCHER_IMAGE (версия), DISPATCHER_HOST (адрес),
DISPATCHER_OWNER (логин), PUBLIC_PORT (8090), LISTEN_IP (0.0.0.0). Пароль передаётся
через временный файл 600, который контейнер удаляет после первоначальной настройки.
Приватный ключ CA, база и connection.json лежат только в instance/data.
Изменение образа поверх рабочей базы требует согласованного обновления/отката.

Запуск диспетчера не включает EXTERNAL на сайте: полный путь проверяется с реальным
обработчиком до переключения рабочих загрузок. Существующий Nginx сайта и его .env
пакет не изменяет. Чужие базы, сервисы и firewall не перенастраиваются.
