# platform-dl-worker-server

Внешний обработчик тяжёлых задач платформы: забирает задачи из очереди основного сервера
исходящим соединением, выполняет их локально и возвращает результат в штатное хранилище.

Входящий порт, туннель и доменное имя обработчику не нужны — сервер к обработчику
не подключается. Обработчик настраивается базовым URL сервера и собственным токеном.

## Состояние

Код не начат. Архитектура, имена, этапы и контракт API согласованы 2026-10-12
и зафиксированы в планах основных репозиториев:

- бэкенд — `serverBreasts/docs/plan/media-workers-plan.md` (решения, контракт `/api/worker/**`);
- фронтенд — `front/docs/plan/media-workers-plan.md` (экран «Обработчики», настройки, журнал);
- приёмка — `front/docs/testing/media-workers.md`.

Задачи этого репозитория — [docs/future-tasks.md](docs/future-tasks.md).

## Коротко об устройстве

- Node (TypeScript), запуск нативным процессом под `launchd`; Docker на Apple Silicon
  не используется: в виртуализированном Linux недоступны VideoToolbox и Metal/ANE.
- Тяжёлые инструменты (`ffmpeg`, распознавание речи) вызываются как внешние процессы
  и обновляются независимо от кода обработчика.
- Обработчик не медийный: тип задачи несёт доменный префикс (`media.transcribe`,
  позже `course.cover`, `backup.dump`).
- Обновление автоматическое: таймер сверяет теги репозитория и переходит на новый тег
  только при отсутствии активной задачи.
- Секреты (токен, базовый URL) живут в локальном файле конфигурации вне репозитория.
